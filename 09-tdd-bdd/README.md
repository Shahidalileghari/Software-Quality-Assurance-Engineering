# 09 — TDD and BDD

## TDD cycle
Red: write a failing test. Green: implement the simplest behavior that passes. Refactor: improve design while keeping tests green.

## BDD
Describe behavior with examples in domain language: Given a context, When an action occurs, Then an observable outcome follows.

Use TDD as a design feedback loop, not as a rigid ceremony. BDD examples should clarify collaboration and acceptance, not become brittle scripts.
