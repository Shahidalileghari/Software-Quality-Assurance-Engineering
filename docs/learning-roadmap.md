# Learning roadmap

## Stage 1 — Foundations
Understand quality, verification vs validation, defects, failures, test levels, test types, and the test pyramid. Learn to turn requirements into observable acceptance criteria.

## Stage 2 — Test design and manual QA
Practice equivalence partitioning, boundary-value analysis, decision tables, state transitions, exploratory charters, risk-based prioritization, and reproducible defect reports.

## Stage 3 — Automated tests
Write focused unit tests, integration tests against real boundaries, API tests, contract checks, and browser E2E tests. Learn setup/teardown, fixtures, deterministic data, isolation, and test doubles.

## Stage 4 — Shift-left and quality engineering
Use TDD where it improves design, static checks, coverage thresholds, accessibility checks, security test cases, and performance baselines.

## Stage 5 — Production readiness
Design CI quality gates, flaky-test handling, test observability, release confidence, rollback criteria, and risk-based regression suites.

Recommended cadence: 60–90 minutes per session. Keep a QA journal containing test intent, assumptions, edge cases, outcomes, and lessons.
